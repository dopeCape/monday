# Workflows are JSON documents the Agent writes, and an agentic Workflow is a one-step special case

Users author Workflows by describing them; the Agent writes the artifact. We decided every Workflow is one JSON document (name, the sentence asked for, kind, trigger, conditions, steps, standing approvals, placement, version) validated against a schema monday owns. Hybrid Workflows have typed action steps and typed model steps. An agentic Workflow is the same document with a single agent step holding instructions, a tool allowlist and a budget. The Agent never writes code for a Workflow, and the user can always read the JSON as "Source" or hear it as prose.

## Considered options

- A prompt file for agentic Workflows and JSON for hybrid. Rejected: two schemas, two source views, two run engines.
- TypeScript Workflows generated by the Agent. Rejected: generated code cannot be sandboxed safely on the Server and contradicts the "the Agent edits data, never code" principle.

## Consequences

- One engine runs both kinds: a deterministic step runner where a model step or agent step is just a step whose executor calls a Runtime.
- Steps beyond the built-in catalog come from MCP servers the user adds, so extension is data too.
- Every edit creates a new version and keeps the old one, so a Run always references the version it ran under.
