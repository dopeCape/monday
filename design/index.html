monday

Design lock-in for the desktop client. Stream is the default layout, every layout is composed from knobs the agent can turn, seven palettes in light and dark. Click any preview to open it full size.

Layouts

Not three fixed screens. A layout is three values, nav (full, rail, hidden), agent (bottom, left, right) and list (stream, split), and a preset is just a named combination. The fourth preview is what happens when you ask the agent to hide the sidebar and move itself to the right.

Screens

Everything beyond the inbox. Workflows and routing are authored by talking to the agent, so those pages are about reading and adjusting, not building.

Palettes

Shipped color schemes. On Linux the same tokens come from ~/.config/monday/monday.toml, so a rice can drive the client. Each palette has a light and a dark half.

What the agent can change

The interface is data. The agent edits values and picks from a catalog, it never writes code into the app, so it cannot break or slow the client and every change is one line in the config file with an undo.

Tokens

Palette, accent, font, size, density, radius. "Make it warmer", "bigger text", "less rounded", "match my terminal".

Composition

Nav full, rail or hidden. Agent bottom, left or right. List as stream or split. Pane widths. "Put yourself on the right, hide the sidebar."

Views

Named layouts with a shortcut, per account. "Make a writing mode with just compose and you." Switch with ⌘1, ⌘2, ⌘3.

What surfaces show

Stream sections and their order, row fields (snippet, tags, avatar), brief on or off, thread collapsing. "Section by project instead of urgency."

Actions and shortcuts

Buttons on the reader toolbar or list rows, scoped to a group. Key remaps. "Give invoice threads a forward-to-accounting button."

Panels from a catalog

Small built-in panels the agent can place: today's calendar strip, a waiting-on counter, pinned notes, a workflow status strip. Custom CSS stays a file for ricers, opt-in.

Type and icons

Geist for the interface, Geist Mono for shortcuts and config. Phosphor icons at regular weight, fill weight only for state.

Principles

What every screen is held to.

Speed first

Nothing waits on the model. Briefs and tags are pre-computed on the server, the list renders from local data, and the agent streams in beside it.

Agent is a peer, not a feature

It can do anything you can: search, draft, send, delete, forward, reroute, change a setting, write a workflow. Anything that leaves the mailbox asks first.

Plain language over editors

Workflows and routing rules are sentences the agent wrote. You change them by talking, and can always read the source.

Everything is a token

Colors, density, font, layout and shortcuts are config values. A user, a rice, or the agent can set them, and the file is the truth.

Quiet surfaces

Hairline borders, one accent, no glows. Color is reserved for state and tags so the mail itself is the loudest thing on screen.

Keyboard complete

J/K to move, E to archive, / to talk to the agent, ⌘K for everything else. The mouse is optional.
